The platform

Three components. One nervous system.

Each part is purpose-built in the language best suited to its job and connected through a single OpenAPI contract.

Rust

Remote Agent

A lightweight async agent deployed on your hosts. It runs checks concurrently, caches results while offline and keeps itself up to date.

  • ICMP ping with configurable intervals
  • Zero-config secure claim workflow
  • Config hot-reload (file watch & SIGHUP)
  • Offline-first result cache
  • Self-upgrade & plugin system
  • Interactive TUI agent-cli
smotra-monitoring/agent →

Go

API Server

The central brain. Collects results, orchestrates agents and exposes a typed REST API generated from an OpenAPI 3.0 specification.

  • Multi-tenant: tenants → sections → agents
  • API-key agent authentication
  • Idempotent result ingestion (UUIDv7)
  • Heartbeats with host vitals
  • Prometheus metrics & structured logs
  • SQLite or PostgreSQL + TimescaleDB
smotra-monitoring/server →

TypeScript

Web Dashboard

A fast, framework-free dashboard with a Bento-box layout, built mobile-first from 320px phones to ultra-wide displays.

  • OAuth2 + PKCE (Okta, Auth0, Azure AD, Google, OIDC)
  • Agent states widget with live status
  • Refresh manager: off / 5s / 15s / 30s
  • System, light & dark themes
  • WCAG 2.1 AA accessibility
  • Generated OpenAPI client

Architecture

From edge probe to dashboard

Agents form a full or partial mesh, probing each other and predefined targets. They ship only metrics to the API server, which stores and serves them to users via browser, CLI or REST API.

  1. 01

    Register

    On first start the agent generates a UUIDv7 ID and a claim token, sending only its SHA-256 hash to POST /agent/register.

  2. 02

    Claim

    An administrator claims the pending agent from the dashboard via POST /agents/claim.

  3. 03

    Receive key

    The agent polls claim-status, receives its API key exactly once and stores it securely.

  4. 04

    Monitor

    Agents probe peers and targets, then send metrics and heartbeats to /v1/agent/{id}/results and /heartbeat with idempotent deduplication.

Capabilities

Engineered for resilient insight

Offline-first by design

When the server is unreachable, agents cache results locally and flush them on reconnect. Client-assigned UUIDv7 IDs make re-submission safe and idempotent.

Hot-reload config

Edit the file or send SIGHUP. Changes apply without restarting the agent.

Self-upgrade

Background version checks and safe binary replacement keep the fleet current.

Security first

Hashed claim tokens, one-time key delivery, 0600 key files and PKCE-based OAuth2.

Observable core

Prometheus metrics, /healthz probes, request IDs and structured slog logging.

Contract-driven

A single OpenAPI 3.0 specification generates the Go server handlers, the Rust agent client and the TypeScript dashboard client — no drift between components.

Roadmap

Where we are heading

  1. Foundation shipped

    ICMP monitoring, claim workflow, heartbeats, result ingestion, OAuth2 dashboard, theme & refresh managers.

  2. More check types in progress

    TCP, UDP, HTTP GET and traceroute checks; disk-backed cache persistence; claiming UI.

  3. Visualisation

    Performance charts, historical data, health trends, filtering, sorting and custom dashboards.

  4. Scale & operate

    Docker Compose, Kubernetes Helm charts, virtual scrolling for 1000+ agents, PWA & offline mode, plugin marketplace.
